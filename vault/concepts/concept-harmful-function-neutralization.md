## Overview

**Harmful Function Neutralization** is the set of systematic moves for dealing with
the **harmful functions** that a [[concept-function-analysis|function model]]
surfaces — distinct from [[concept-trimming|trimming]] (which removes *components*
and redistributes *useful* functions) and from contradiction resolution (which
resolves *trade-offs*). It answers: a harm remains after trimming, or exists in a
system you cannot trim — now what?

## Key Properties

A rough hierarchy of responses, most-ideal first (prefer earlier options):
1. **Eliminate the cause** — use [[concept-cause-effect-chain-analysis|CECA]] to
   find and remove the root cause of the harm (the harm never arises).
2. **Block / shield / isolate** — introduce a substance or barrier between the harm
   source and the affected object (su-field "introduce S3").
3. **Counteract** — add an opposing effect/field that cancels the harm.
4. **Convert harm to benefit** — redirect the harmful effect to do useful work
   (the principle behind [[principle-22-blessing-in-disguise|Principle 22]]); the
   most ideal outcome because it uses an existing [[concept-resources|resource]].
5. **Make the harm acceptable** — reduce it below a threshold (last resort; a
   partial, lower-ideality move).
- Maps to the **harmful-complete-system** class of the
  [[concept-76-standard-solutions|76 Standard Solutions]] (subgroup 1.2).

## Connections

Completes the [[concept-function-analysis|function-analysis]] tool family alongside
[[concept-trimming|trimming]]; depends on
[[concept-cause-effect-chain-analysis|CECA]] to locate the harm's root.
