## Overview

The vault documents the individual TRIZ tools but not **when** and **in what
order** to apply them for a product-development goal. This note is the
**choreography** layer: it groups the tools and lays out the typical sequences —
the "method substrate" the project's
[[decision-cli-triz-agentic-strategy|strategy]] calls for. (Composable building
blocks chaining into product-development jobs is a structural idea; the method
content here is drawn from independent references, not from any one curriculum.)

## Key Properties

**Two kinds of tools:**
- **Analytical** (find the right problem): [[concept-function-analysis|function
  analysis]], [[concept-cause-effect-chain-analysis|CECA]],
  [[concept-su-field-analysis|su-field analysis]].
- **Solution** (resolve it): [[concept-trimming|trimming]],
  [[concept-feature-transfer|feature transfer]],
  [[concept-separation-principles|separation]] / contradiction resolution,
  [[concept-76-standard-solutions|standard solutions]], the
  [[concept-harmful-function-neutralization|harmful-function]] moves.

**Typical sequences:**
- *Resolve a field problem:* function model → CECA → key disadvantage →
  formulate contradiction → separation / principles → check vs
  [[concept-ideality|IFR]].
- *Simplify / cut cost:* function model → trimming → handle secondary problems →
  contradiction resolution.
- *Hard / novel problem:* escalate to [[concept-ariz|ARIZ]] (opt-in).

**Mapping to product-development jobs** (TRIZ-from-the-start):
discover needs → create offerings (define functions, design toward ideality) →
design & prototype (surface and resolve contradictions early) → reduce burdens
(trim) → resolve field problems → evolve (trends). Each job is an analytical pass
then a solution pass.
