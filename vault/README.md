# triz vault

A [vaultmind](https://github.com/peiman/vaultmind) knowledgebase for **TRIZ** —
the Theory of Inventive Problem Solving (Russian: *Теория решения
изобретательских задач*, Altshuller).

This is associative research memory: atomic, typed, cross-linked markdown notes
that vaultmind indexes and retrieves. It is the single source of truth for what
the project knows about TRIZ. It is **not** the OMC working memory
(`~/.claude/.../memory/`), which holds cross-session operational facts.

## Layout

| Directory | `type` | Holds |
|-----------|--------|-------|
| `concepts/`  | `concept`, `case-study` | TRIZ ideas + the de-facto sub-kinds below; plus worked `case-study` notes (own type) |
| `sources/`   | `source`   | Literature — Altshuller's books, papers, standards. One note per source, with a `**Citation:**` line |
| `people/`    | `person`   | Theorists and practitioners (Altshuller, etc.) |
| `decisions/` | `decision` | Project/architecture decisions (ADR-style) |
| `projects/`  | `project`  | Project-level notes (`proj-triz`) |
| `templates/` | —          | Frontmatter/body templates (`concept`, `source`, `person`, `project`, `decision`, `reflection`, `case-study`, plus `principle`/`parameter` reference shapes) |

### `concept` sub-kinds (one `concept` type, distinguished by tag + `number`)

The `concept` type carries several de-facto sub-kinds, identified by a `tags`
entry (and a `number` field where ordinal): **`inventive-principle`**
(`principle-NN-*`, `number` 1–40), **`engineering-parameter`** (`parameter-NN-*`,
`number` 1–39), **`tese-trend`** (`trend-*`), plus core concepts and tools. See
`templates/principle.md` and `templates/parameter.md` for their body shapes.
`case-study` is a first-class type, not a `concept` sub-kind.

`.vaultmind/index.db` (the SQLite index + embeddings) is gitignored — it is
regenerated by `vaultmind index`, never committed.

## Note conventions

- **IDs** are type-prefixed, kebab-case, and immutable once created:
  `concept-contradiction-matrix`, `source-altshuller-1984`,
  `person-genrich-altshuller`, `decision-…`, `proj-triz`.
- **Filename** = `<id>.md`.
- **Frontmatter** follows the matching template in `templates/` (`id`, `type`,
  `title`, `created`, `tags`, `related_ids`, `source_ids`, plus type-specific
  fields). Validate with `vaultmind frontmatter validate`.
- **Links** use Obsidian-compatible wikilinks: `[[filename|Display Text]]` —
  e.g. `[[concept-ideality|Ideality]]`, never `[[Ideality]]`. CLI commands stay
  in backticks, not wikilinks.
- **`source_ids`** on a concept/person point to the `source-*` notes backing its
  claims. A cited KB means every non-obvious claim traces to a `source` note.
- **`confidence`** (`high` | `medium` | `low`) is an optional, queryable field
  recording the provenance strength of a note's claims — `medium` flags notes
  with documented uncertainty (e.g. contested dates, disputed sub-principle
  lettering, teaching-example case studies). It makes our uncertainty-flagging
  discipline machine-filterable.
- **`number`** is the ordinal on `principle-*` (1–40) and `parameter-*` (1–39)
  notes — the field a future CLI reads to map matrix cells to principles.

## Working with the vault

```bash
# Recall (pointers first, then read bodies by id)
vaultmind ask "contradiction matrix" --vault vault --pointers-only
vaultmind note get concept-contradiction-matrix     # tracked read

# Re-index after editing notes (incremental; --full to rebuild)
just vault-index            # = vaultmind index --embed --model bge-m3 --vault vault

# Health (unresolved links, embedding coverage, Obsidian-incompatible links)
vaultmind doctor --vault vault
vaultmind lint --fix-links  # bulk-fix wikilinks
```

## Embedding model

This vault is embedded with **bge-m3** (hybrid dense + sparse + ColBERT), which
gives meaningfully better-calibrated retrieval confidence than the pure-Go
`minilm` default. bge-m3 requires an **ORT-tagged** vaultmind binary:

```bash
# one-time, in the vaultmind source repo:
bash .claude/scripts/setup-ort.sh   # needs onnxruntime (e.g. brew install onnxruntime)
task build:ort                      # produces an ORT-tagged binary
```

The ORT binary is a superset (does minilm too) and is installed as the default
`~/go/bin/vaultmind` here. If you only have the pure-Go binary, switch the
`just vault-*` targets back to `--model minilm` — queries still work, but
bge-m3 *indexing* on pure-Go is hour-slow.

The four vaultmind hooks (recall on prompt, context at session start, read
tracking, episode capture) are wired in `.claude/settings.json` and point at
this vault.
